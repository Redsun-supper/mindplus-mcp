### 缺陷 1：安装脚本认不出「缩进」的 DSH 条目（真实踩中）
`applyYaml` 的标记正则原来是 `^- id:\s*mcp-<name>\s*$`（锚定列 0）。但 DSH patch 条目常嵌在顶层 `- insert:` 列表里，是 `    - id: mcp-mindplus`（缩进 4）。结果脚本判定"未注册"，在列 0 **又追加了一份重复条目** → 同一 id 出现两次，会污染 loader patch。
**修复**：正则改为 `^\s*- id:\s*mcp-<name>\s*$`；`stripYamlBlock` 重写为按**缩进层级**消费（marker 缩进为基准，吃掉所有更深缩进的行，遇到同级或更浅的行停止），而不是假设列 0。新增 `escapeRegExp` / `yamlEntryId` 两个辅助函数。

### 缺陷 2：安装测试没有隔离，会改真实配置（真实踩中）
`test/install-smoke.mjs` 里不带 `--target` 的调用会让脚本**同时作用于本机真实存在的 `~/.claude.json` 和 5 个 DSH profile**。跑一次 `--uninstall` 就真把用户的 `core-017` 注册和 Claude Code 注册删掉了。
**修复**：`run()` 给子进程注入沙箱环境变量 —— `HOME` / `USERPROFILE` / `APPDATA` 全指向临时目录，使自动探测在沙箱内找不到任何真实配置。并新增第一条断言 `sandbox: no real client config is visible`（要求所有 target 的 `present === false`），一旦隔离失效立刻失败。
**善后**：5 个 DSH profile 已从安装前备份 `*.bak-2026-10-11T00-52-20-300Z` **逐字节还原**（`cmp -s` 验证通过）。

### 缺陷 3（小）：`--uninstall` 不是严格还原
`stripYamlBlock` 原本强制补行尾换行，导致原文件（无行尾换行）被改动一个字节。已改为保留原始的行尾换行状态。

### 测试
`test/install-smoke.mjs` 13 → **16 项**（新增沙箱隔离守卫 + 缩进条目识别 + 缩进条目卸载）。**16/16 通过**。
`smoke.mjs` / `http-smoke.mjs` 本轮未跑：**Mind+ 当时没在运行**（`127.0.0.1:19302` 无监听）。

### 经验（重要）
- 写「修改用户环境」的脚本测试时，**必须沙箱化 HOME/APPDATA/USERPROFILE**，否则默认行为会打到真实配置上。

## 新增「界面识别与点击」能力（44 → 67 个工具）

### 需求
用户要：截图发给 AI → AI 给点击位置 → MCP 执行点击；外加拖动等自动化，以及一个识别框架。

### 架构（新增 4 个源文件 + 1 个 PowerShell 主机）
```
tools.js → automation.js ─┬→ gui.js ─(JSON-lines over stdio)→ gui-host.ps1 → Win32
                          ├→ vision.js → HTTP/CLI → 多模态模型
                          └→ image.js（纯 JS PNG 编解码 + 匹配/找色）
```
- **`src/gui-host.ps1`**：**常驻** PowerShell 5.1 进程，内嵌 C#（P/Invoke）做截屏 / SendInput / EnumWindows / 剪贴板。用常驻是因为 `Add-Type` 冷启动 1~2 秒，视觉循环动辄 7~8 步，每步重启进程不可接受。
- **`src/gui.js`**：主机客户端。进程死了自动重启；`stop()` 先 `stdin.end()` 再 kill。
- **`src/image.js`**：零依赖 PNG 解码/编码（`node:zlib` + 手写滤波器/位深/色彩类型）+ 模板匹配 + 找色 + 盒式缩放 + 标注。
- **`src/vision.js`**：可插拔提供者（openai / anthropic / ollama / command / none）、提示词构造、容错 JSON 解析、坐标换算。
- **`src/automation.js`**：抓屏 → 识别 → 执行的编排，以及 `runVisionLoop` 视觉循环。

### 关键设计决定
- **GUI 层不经过 mind-link**，直接本机起进程 → **Mind+ 没开也能用**。
- 坐标三层：屏幕物理像素 ←(恒等)→ 截图像素 ←(缩放 maxWidth)→ 模型看到的图。收在 `transform={offsetX,offsetY,scale}` 里，`screenX = offsetX + imageX/scale`。
- 提示词**要像素坐标不要归一化**、**要求模型能说 found:false**、**要 alternatives** 兜底。
- `vision_act` 有硬上限 `maxSteps`（默认 8）+ `allowed` 白名单 + `dryRun`（走完整循环但不注入输入，且只走一步）。history 只回喂最近 10 条。
- **所有输入类工具都有 `dryRun`**。

### 实际踩到的坑（都修了）
1. **`Add-Type` 把编译警告当错误** → C# 里一个没用到的私有字段就让主机起不来。必须零警告，且只能用 **C# 5 语法**（PowerShell 5.1 带的老 csc：无字符串插值、无 `?.`、无表达式体成员）。
2. **`GetWindowTextW` 传 `null` 缓冲区查长度在 .NET Framework 的 StringBuilder 封送下不工作**（返回 0）→ 一开始所有窗口标题都是空串。必须老实分配缓冲区。
3. **`GetWindowThreadProcessId` 的第二参数**要声明成 `out uint`，传 `IntPtr.Zero` 拿不到 PID。
4. **argv 模板不能用 `split(/\s+/)`** —— Windows 路径带空格、命令行带引号。写了引号感知的 `tokenizeCommand`（引号内反斜杠保持字面）。
5. **PowerShell 把 .NET 异常包一层 `MethodInvocationException`**，消息是本机化样板文字 → catch 里优先取 `InnerException.Message`。
6. 剪贴板：`Clipboard` 要 STA，PowerShell 主线程不保证 → 每次起临时 STA 线程 + Join。

### 实测数据（本机）
- 显示器：主屏 2560×1440 @96dpi(100%)，副屏 1920×1080 @144dpi(150%)，虚拟桌面 4480×1440。
- **`awareness = per-monitor-v2`**（`__COMPAT_LAYER=HIGHDPIAWARE` + 运行时 `SetProcessDpiAwarenessContext(-4)` 都生效了），副屏 `scale` 正确报 1.5，点击落点准确。
- SendInput 绝对坐标必须带 `MOUSEEVENTF_VIRTUALDESK` 才能点到副屏（可能为负坐标）。

### 测试
新增 `test/gui-smoke.mjs`（**30 项**）与 `test/fixtures/fake-vision.mjs`（假模型）。
- **不点任何东西**：全部 `dryRun`；跑完还原光标 + 剪贴板 + 删截图目录。
- 模板匹配用「从同一张截图裁模板再找回去」，断言坐标精确 `(150,110)`、`score===1` —— 确定性覆盖 PNG 解码→裁剪→编码→解码→匹配→坐标映射整条链路。
- 视觉链路用假模型跑通，**不需要 key / 不需要联网**。
- 四套全绿：install **16/16**、gui **30/30**、smoke **16/16**、http **7/7**。

### 未验证
**`vision_*` 接真实模型的行为没测过**（本机没配 key，Ollama 也没在跑，`127.0.0.1:11434` 无响应）。首次使用请先 `vision_config{test:true}`。

### 经验
- 给 Windows 做无依赖 GUI 自动化：**常驻 PowerShell + 内嵌 C# P/Invoke** 是可行的，但要注意「警告即错误」和 C# 5 语法限制。
